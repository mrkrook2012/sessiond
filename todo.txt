this way, using the sysd systmctl to restart will also work. 
the stop and start sysd versions will not create new session, they will toggle 
the initializion of the session will be plugged into the load feature of sysd.

The yaml file should contain the windows whose outputs are tracked. 
The internal start should only end when a tracked window ends or fails.

Cli sketch
myapp run <command> [args...] // Creates new session
myapp run --systemd <command> [args...] // Creates new sysd service running that command

// General commands
myapp list
myapp attach <name>
myapp kill <name>
myapp kill --all

// Only for sysd based
myapp service start <name>
myapp service stop <name>
myapp service restart <name>
myapp service enable <name>
myapp service disable <name>

// Should only work for ephemoral sessions
myapp export <name>
myapp import <file>

// Commands to check on daemon
myapp daemon start
myapp daemon stop
myapp daemon status

// Internal commands used in sysd
myapp __internal-systemd-start <config yaml path>
myapp __internal-systemd-stop <name>
